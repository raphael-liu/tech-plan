# 输入理解与多轮访谈

[English](intake.en.md)

## 材料驱动

确定材料覆盖的团队、时间及用途。长文先定位目标、关键进展、风险、资源、决策、复盘等章节，再读取理解关系所需的上下文。扫描件先 OCR，涉及数字、表格归属或关键判断时核对原页；不可读取的内容报告缺失，不能猜补。

建立简洁证据台账，按需附在成稿：

| 编号 | 时间与来源定位 | 事实/陈述及范围 | 对应目标/问题/项目 | 类型与可信边界 | 冲突或待验证点 |
|---|---|---|---|---|---|

重建变化链：原计划想改变什么 → 当时为何选择 → 已投入和已交付什么 → 结果是否出现 → 哪些约束/判断已变化 → 本期继续、调整或停止什么。分别保留“原定”“报告完成”“已验收”“价值已验证”的状态。

跨材料冲突先核对时间、统计口径、业务范围与版本，记录双方来源。能独立核实的先核实，仍影响决策时集中追问；不以材料数量投票，不把最新陈述自动当成真实结果。

## 对话驱动

每轮通常问 1–3 个相关且能改变下一步判断的问题，给自然叙述空间。先简短反馈当前理解和决策影响，再提问；不换措辞重复已回答内容，不一开始抛出六章几十个问题。

优先补方向性缺口：团队使命、本期结果、现状差距、硬约束、关键冲突。再沿最可能失效的环节深挖。以下是可选问题，不是固定问卷：

| 环节 | 高信息量追问 | 改变的判断 |
|---|---|---|
| 价值与边界 | 周期结束时，谁的什么结果必须改变？哪些事情本团队不能拍板？ | 目标和权限 |
| 诊断 | 有哪些事件和数据？什么证据区分技术瓶颈、组织激励和流程问题？ | 根因和验证 |
| 取舍 | 保住这一项愿意延后什么？代价落在谁身上？资源增加还这样选吗？ | 机会成本和约束 |
| 排序 | 后续必须等哪个产出？哪些事都抢同一位骨干？若只保一项保哪项？ | 依赖和可行投入 |
| 对齐 | 哪位负责人承诺了什么资源、产出和时间？有什么记录？谁会反对？ | 承诺和阻力 |
| 节奏 | 第一处能验证判断且能停下的位置在哪？何种信号阻止扩大？如何恢复？ | 风险和退路 |
| 校准 | 什么信号让你放弃原判断？最早何时看得到？触发后回到什么决策？ | 改判和止损 |

用户给出解决方案时，先理解其结果、证据和约束，不直接认定其为需求或错误。争议处列不同解释和区分它们所需的最少信息。

## 跨轮记录与停止条件

保留紧凑摘要：已知事实及来源、当前诊断、决策/假设、已排除路径、未决冲突、下一轮关键问题、受影响章节。只在有助于确认理解时展示，不每轮全量输出。

目标周期清楚、主要约束已识别、核心诊断有依据或可验证假设、取舍排序可解释、资源/承诺与启动条件已区分时，即可成稿。负责人、阈值、预算未知时可交付草案，标明执行限制。

缺口若会颠倒方向或造成不可承诺的排期，问清后再依赖它做结论，其他工作继续。用户不希望继续回答时，以有条件的方案和最少待决事项交付，不把沉默当同意。

## 跨语言证据

访谈与输出语言按用户要求选择，不由材料语言决定。保留来源原始标题与定位，可附解释性译名；跨语言合并别名时不能误并不同系统或团队。估算、建议、承诺、验收与收益已验证等状态在翻译中保持区分。用户切换语言时延续证据台账和未决问题，不重新访谈。
